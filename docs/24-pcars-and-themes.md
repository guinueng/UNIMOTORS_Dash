# Project CARS 1 수신 어댑터와 선택형 테마

구현·검증일: 2026-11-01. PCARS 1 **PC판 UDP v1** 대상이다. PCARS 2/3·Windows 공유 메모리 리더는 구현하지 않았다.

2026-11-02 추가: **게임 좌표 저장·서킷 지도·도면 자동 선택**을 구현했다. 두 테마의 ‘서킷 지도’ 또는 `/game-map`에서 열 수 있다. 전체 시험은 114개로 늘었으며 [지도 기능과 검증 범위](25-game-track-maps.md)를 참고한다. 아래 101개는 첫 수신기·테마 통합 시점의 검증 기록이다.

## 바로 실행

1. Python 3.11 이상을 설치하고 이 브랜치의 저장소를 준비한다.
2. 게임의 `Options & Help → Gameplay → UDP Frequency`를 5로 설정하고 실제 주행 세션에 들어간다. 다른 UDP 5606 수신 앱은 종료한다.
3. 저장소 루트에서 아래 명령을 실행한다. 이 명령은 GPS/CAN/BMS 장치를 열지 않는다.

```powershell
python vehicle/pcars_receiver.py --bind 0.0.0.0
```

4. PC에서 `http://127.0.0.1:8080/`을 연다. 휴대폰과 iPad는 같은 로컬망에서 `http://PC의IPv4주소:8080/`을 연다. S25 Ultra와 iPad Air 13인치는 가로 배치한다.
5. 화면의 **테마 선택**에서 `v7 연구형` 또는 `Claude 클래식`을 선택한다. `/` 접속 시 해당 브라우저의 이전 선택을 복원한다. URL의 `?theme=v7` / `?theme=claude`가 저장된 선택보다 우선한다. `/legacy`는 Claude 클래식의 별칭이다.

처음에는 로컬 표시·CSV만 실행하며 외부 전송은 꺼져 있다. GPS/BMS 라이브러리 설치는 불필요하다. 다음과 같이 기존 v7 피트 서버를 명시하면 영구 큐와 ACK를 통해 전송한다.

```powershell
python -m pip install websocket-client
$env:UNIMOTORS_TOKEN='서버와 같은 설정 토큰'
python vehicle/pcars_receiver.py --bind 0.0.0.0 --upload --server ws://서버주소:8090/ingest
```

기본 식별자는 `pcars1`이다. 실험별로 `--vehicle pcars1-p01-a`처럼 지정할 수 있다. 실차 `car1` 이름은 거부한다. 새 프로세스는 새 게임 세션을 만들며 이전 게임을 실차의 배터리 복원 절차로 합치지 않는다. 기본 로그는 실행 폴더의 `pcars_logs/`, DB는 그 아래 `state/pcars1/`이다. `UNIMOTORS_STATE_DIR`가 있으면 그 폴더 아래 `pcars1/`만 사용한다. 실제 차량과 데모 DB를 덮어쓰지 않는다.

## 수신·데이터 처리

- UDP 5606을 독점 바인딩하고, 전체 인터페이스 수신 시 224.0.0.1 그룹에도 가입한다. 다중 NIC/VPN 환경에서는 `--multicast-interface PC의로컬IPv4`로 수신 네트워크를 지정할 수 있다. WireGuard만으로 LAN 방송이 전달되지는 않는다.
- `--source 게임PC의IPv4`로 발신자를 고정할 수 있다. 생략하면 첫 유효 텔레메트리 발신 IP를 프로세스 종료까지 유지한다. UDP 출처 제한은 암호학적 인증이 아니다.
- 3바이트 헤더와 텔레메트리 1367바이트, 문자열 1347바이트, 추가 문자열 1028바이트 구조를 구분한다. PCARS 2의 12바이트 헤더 구조를 적용하지 않는다. 잘못된 길이·비유한 속도·참가자 범위를 거부한다. 헤더의 build는 기록하지만 모든 게임 패치의 호환성을 확인한 것은 아니다.
- 6비트 순서 번호의 중복·근접 역순을 거부한다. 0.4초보다 긴 단절 후에는 순서 기준을 다시 잡는다. 직전 패킷과 바이트가 완전히 같은 반복 패킷은 단절 후에도 최신성 시간을 갱신하지 않는다. 전송 시각이 없는 UDP이므로 수신 시각 기준이며 장시간 지연 패킷의 절대 생성 시각은 알 수 없다.
- 유효 텔레메트리 수신 후 1.5초가 지나면 속도·현재 랩 시간·기어·RPM 등 현재 값을 비운다. 문자열 패킷은 속도의 최신성을 갱신하지 않는다. 브라우저 SSE 중단에도 별도 1.5초 감시가 동작한다.
- 메뉴·일시정지·재시작·리플레이·경기 종료는 주행과 구분한다. 일시정지에서 복귀할 때 같은 경기로 유지한다. 코스/차종 문맥 변경, 메뉴/리플레이/종료 후 새 주행, 참가자 전환, 랩 수 감소, 5초 초과 단절 후 재개는 새 기록 세션으로 나눈다. 바뀐 세션과 단절은 실제 게임 사전 시험에서 확인해야 한다.
- 선택된 참가자의 게임 랩 수·현재/최근/최고 시간을 사용한다. GPS 출발선을 가상 좌표로 속이지 않는다. 게임 화면에서 다른 참가자를 관전하면 대상도 바뀔 수 있으므로 참가자 시점을 고정한다.
- 게임이 관리하는 세션·랩·프로파일은 웹 제어 API에서 변경할 수 없다. 표시 설정과 기록 내려받기는 가능하다.

|항목|표시·기록 의미|
|---|---|
|속도|게임 m/s를 km/h로 변환|
|RPM·기어·연료 %·냉각수|게임 원본 계기 정보. 연료는 SOC가 아님|
|랩 시간·완료 랩·순위|게임 네이티브 값. 경기 공식 계측과 별개|
|G-G|SDK 로컬 X/Z 가속도 ÷ 9.80665. 방향 부호를 실제 IMU 축과 검교정하지 않음|
|게임 좌표·궤적|X/Y/Z 정수 좌표·랩 거리·트랙 길이 저장. `/game-map`에서 게임 전용 서킷 지도와 조회|
|GPS 좌표·방위·실제 이동거리|미제공. 게임 좌표로 실제 위치를 생성하지 않음|
|SOC·팩 전압·전류·셀 편차·Wh/Ah/에너지 증분|미제공(null/CSV 빈칸). 0 소비로 기록하지 않음|

공통 v7 CSV와 서버 스키마를 유지하며 게임 전용 항목·원본 순서 번호·수신 상태·차종/트랙·좌표·랩 시계는 `meta.input`과 `meta.lap_timing`에 보존한다. 참가자 이름 블록은 읽거나 저장하지 않는다. 기록은 CSV 표본 주기(기본 0.2초)로 저장하며 원본 UDP 전체를 보관하는 도구는 아니다. 게임 지도는 별도 `/game-map`을 사용하며 피트의 기존 GPS 지도·EV 에너지 분석과 구분한다.

## 두 테마의 비교

|v7 연구형|Claude 클래식|
|---|---|
|왼쪽 속도, 오른쪽 큰 랩 시계, 하단 네 가지 지표|기존 검은 배경·파란 속도와 G-G 다이어그램, 하단 계기 줄|
|기본·내구·정비 화면, 정차 후 설정|속도 중심 간결한 배치. 설정은 v7으로 전환해 사용|
|게임 모드에서 RPM·기어·연료·냉각수|같은 게임 항목에 완료 랩·순위 추가|
|공통 입력·경고·TEAM 메시지·최신성 사용|같은 입력·경고·최신성 사용. 과거 v6의 값 유지 동작은 교체|

자유 주행 중 바꾸는 것은 체험용이다. 연구 비교에서는 조건 순서를 교차 배정하고 같은 차량·코스·기기 위치·노출 시간을 유지한다. 두 테마는 정보량도 일부 다르므로 순수한 색상 효과로 해석하지 않는다. 동일 입력의 반복 재생 도구는 이번 범위에 포함하지 않았다.

## 확인한 범위

- 전체 pytest 101개 통과: 기존 v7·설치·데모 + PCARS 해석/단위/누락/NaN/순서/최신성/상태/세션 분리, 테마 파일 설치 누락 시 기존 설치 보존.
- 외부 PCARS 클라이언트의 공개 캡처 3종을 로컬에서 해석해 텔레메트리(build1122, 정지·N·race not started), 문맥, 추가 문자열 분류와 교차 확인했다. 이 캡처나 타사 구현을 저장소에 복제하지 않았다.
- 실제 로컬 수신 프로세스에 **가상 UDP** 송신 → HTTP/SSE → CSV → 실제 v7 서버 WebSocket/DB/ACK.
- 두 테마 × 800×480, 892×412, 1366×1024의 표시 영역·넘침, 선택 저장·URL 우선, 일시정지·재개·수신 중단 시 현재 값 비움, 게임 세션 조작 거부. JavaScript 오류 없음.
- 실제 게임을 실행한 호환 확인, Pi/DSI 물리 화면, 실제 CAN/BMS·전원 차단·학생 실험은 미수행. 화면 크기 시험은 브라우저 뷰포트이며 S25/iPad 실기 테스트가 아니다.

재현 명령: `python -m pytest -q`, `python scripts/browser-smoke.py`, `python scripts/demo-browser-smoke.py`, `python scripts/pcars-browser-smoke.py`. 마지막 세 명령은 개발 의존성과 Playwright Chromium이 필요하다. 증거 화면은 `.qa/`와 GitHub Actions artifact에 생성된다.

## 수신이 안 될 때

게임이 실제 주행 세션인지, UDP Frequency가 0이 아닌지, PC 개인 네트워크에서 Python의 UDP 5606과 화면용 TCP 8080을 허용했는지 확인한다. 게스트 Wi-Fi/AP 격리는 기기 간 통신을 막을 수 있다. VPN을 켰다면 게임이 보내는 로컬 인터페이스와 수신 인터페이스를 확인한다. 다른 앱이 5606을 점유하면 수신기는 시작 단계에서 오류를 내며 종료한다. `/api/state`의 `input.receiver`에서 유효 수신·형식 오류·중복/역순·다른 발신자 건수를 확인할 수 있다. 형식 오류가 계속되면 게임 버전·패킷 길이를 확인해 디코더 지원 여부를 판단한다.
