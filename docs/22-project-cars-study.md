# Project CARS 1 PC를 이용한 클러스터 평가

검토일: 2026-11-01. 대상은 사용자가 보유한 **Project CARS 1 PC판**이다.

## 가능 여부와 현재 구현 범위

Project CARS 1의 UDP v1 수신·해석 어댑터 `vehicle/pcars_receiver.py`를 v7 화면·CSV·outbox/ACK에 연결했다. 속도·기어·RPM·연료·냉각수와 게임 네이티브 랩 시간을 받아 표시한다. v7 연구형과 Claude 클래식을 선택할 수 있다. **가상 UDP 통신 검증은 완료했으나 사용자 보유 게임의 직접 실행·실제 게임 연결 시험은 아직 수행하지 않았다.** 실행 방법과 정확한 검증 범위는 [수신·테마 안내](24-pcars-and-themes.md)에 정리했다.

텔레메트리 앱 개발사들의 Project CARS 1 연결 안내에서는 UDP 포트 5606의 네트워크 브로드캐스트와 게임 내 UDP Frequency 설정을 확인할 수 있다. PC판은 공유 메모리를 쓰는 연결 방법도 제공한다.

- [RS Dash 개발사의 Project CARS 1 연결 안내](https://www.rsdash.com/rs-dash-pcars1)
- [Sim Racing Telemetry 개발사의 Project CARS 연결·전송 빈도 안내](https://simracingteam.com/games/PCARS/)
- [Sim Racing Studio의 PC판 Shared Memory 설정 안내](https://www.simracingstudio.com/manual-game-config)

이는 실제 연동 앱 개발사들의 1차 설정 자료다. Project CARS 2/3의 패킷 구조를 1편에 그대로 적용하면 안 된다. 다른 상용 게임도 각 게임의 UDP·공유 메모리·SDK에 맞는 입력 어댑터가 필요하며, 한 번 연결했다고 모든 게임을 지원하는 것은 아니다.

## 권장 연결 구조

```text
Project CARS 1 (Windows PC)
       ↓ UDP v1 5606 (현재 구현)
PC의 게임 입력 어댑터 ──→ 선택 필드 기록 (원본 UDP 전체 저장 아님)
       ↓ 값·단위·상태 검증, game 출처 표시
v7 전용 시뮬레이터 세션 / RaceRuntime
       ├─ 웹 계기판 HTTP/SSE → PC 옆 화면 / 휴대폰 / iPad / Pi의 Chromium
       └─ CSV·outbox·ACK → 연구용 서버
```

첫 연결은 게임과 수신 어댑터를 같은 PC에서 실행하는 편이 단순하다. Project CARS 1의 UDP는 브로드캐스트이므로 기존 WireGuard VPN만으로 게임 패킷이 원격 Pi까지 전달된다고 가정하지 않는다. PC에서 먼저 받은 뒤 검증한 데이터만 전달하거나, 계기판 서버도 PC에서 실행하고 다른 기기는 표시 장치로 쓰는 구조가 가능하다. 로컬망 접근·Windows 방화벽·게임의 텔레메트리 설정은 실제 환경에서 확인해야 한다.

게임 UDP 설정은 `Options & Help → Gameplay → UDP Frequency`에서 켠다. SRT 안내의 5는 약 20Hz로 설명되어 있어 최초 수신 시험의 출발점으로 쓸 수 있다. 앱마다 안내하는 빈도가 다르므로 수신 주기·드롭·지연을 직접 기록하고 실험 내에서는 고정한다. 공유 메모리를 선택하면 게임과 리더를 같은 Windows PC에서 실행하고 해당 출력 옵션을 활성화해야 한다.

## 입력 매핑과 데이터의 의미

|항목|연동 방법·제약|
|---|---|
|속도·랩 관련 정보|게임 원본에서 받아 단위를 확인하고 v7 표시값으로 변환한다. 출력 항목은 1편의 실제 패킷/SDK로 검증한다|
|위치|게임 좌표를 실제 GPS로 취급하지 않는다. 가상 경로 투영이 필요하면 game/projected 출처를 명시한다|
|일시정지·메뉴·세션 변경|게임 상태를 구분해 누적·랩 계측을 중단하거나 새 구간으로 나눈다. 같은 값의 반복 수신을 새 주행으로 세지 않는다|
|재시작·차종·코스 변경|게임 세션과 연구 세션을 기록하고 실차 복원 후보와 DB를 분리한다|
|SOC·팩 전압·전류·셀 편차|게임 연료·엔진 데이터를 BMS 값으로 이름만 바꾸지 않는다. 제공되지 않는 값은 미제공으로 표시한다|
|EV 에너지·BMS 경고 평가|별도의 합성 시나리오 또는 검증된 추정 모델을 사용하고 게임 원본과 합성값을 명확히 구분한다|

따라서 우선은 **기본 화면의 가독성·정보 탐색·배치 평가**에 적합하다. 게임만으로 실제 Daly 통신, 실제 팩 에너지 정확도, 재시작 복원의 전원 차단 내구성, 실차 주행 안전성을 검증할 수는 없다.

## 학생 대상 평가안

1. 게임 경험·운전 경험·안경/렌즈 사용 여부를 기록하고 충분한 연습 주행을 제공한다.
2. 차량·코스·날씨·시점·보조 기능·조작 장치를 고정한다. 게임 기본 HUD의 속도·랩 표시가 답을 대신 제공하지 않도록 HUD 조건도 고정·기록한다.
3. 동일 참가자가 화면이나 기기 조건을 바꾸어 평가한다. 순서를 교차 배정하고 조건 사이에 휴식을 둔다. 초보자의 학습 효과를 화면 개선 효과로 해석하지 않는다.
4. S25 Ultra와 iPad Air 13인치는 가로 배치하며, 실제 표시 영역 크기·눈-화면 거리·높이·각도를 기록한다. 게임 주행 상태와 정차 탑승 관찰 결과는 별도 조건으로 분석한다.
5. 한 블록 종료 후 게임을 멈추고 Google Form에 응답한다. 공통 6문항과 가독성·시선 이동 부담·크기·배치 선호를 연결할 수 있다. 기존 3환경 데이터에 게임 결과를 무표식으로 섞지 않고 새 실험 버전/조건으로 수집한다.
6. 정보 탐색 과제를 넣으면 정답률과 응답 시간을 기록한다. 구두 응답 시간은 말하기 시간을 포함하며 순수 시선 탐색 시간으로 부르지 않는다. 주관적인 눈·목 부담 점수 역시 실제 시선 이탈 시간을 측정한 값은 아니다.

모든 참가자에게 주행 입력을 완전히 같게 제시해야 하는 비교는 저장된 게임 텔레메트리를 재생하는 방식이 적합하다. 자유 주행은 참가자마다 속도·랩 상황이 다르므로 같은 과제·코스·노출 시간을 통제한 별도 실험으로 해석한다. A/B/C 9화면 연구 도구와 연동할 때도 모든 레이아웃에 같은 입력과 같은 데이터 출처를 적용해야 한다.

## 실제 게임 사전 시험 순서

1. 사용자의 PC에서 게임 UDP Frequency를 켜고 수신기를 실행한다. 유효 패킷 건수·형식 오류·실제 주기를 확인한다.
2. 게임 HUD와 속도·기어·RPM·현재/최근/최고 랩 시간을 대조한다. 게임 관전 대상과 UDP 참가자 선택을 확인한다.
3. 메뉴·일시정지·레이스 재시작·게임 종료·코스 변경을 실제로 수행해 표시 비움과 세션 분리를 확인한다.
4. S25 Ultra와 iPad Air의 실제 가로 배치에서 표시 크기·지연·화면 위치를 확인한다.
5. 기기별 표시·설문 흐름을 사전 평가하고 본 실험 조건과 테마 비교 순서를 확정한다.
