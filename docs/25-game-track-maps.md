# 게임 좌표 저장과 서킷 지도 · 2026-11-02

Project CARS 1 UDP 수신기에 게임 좌표 기록과 별도 지도 화면을 추가했다. 코스를 미리 정할 필요는 없다. **서킷 이름과 코스 버전으로 도면을 자동 선택**하고, 준비된 도면이 없는 코스는 주행 궤적부터 표시한다.

## 열기

[수신기 실행](24-pcars-and-themes.md) 후 두 테마의 **서킷 지도 ↗**를 누르거나 `http://PC주소:8080/game-map`을 연다. 피트 서버에도 `/game-map`이 있다. 피트에서는 게임 식별자(기본 `pcars1`)를 선택한다. 사용자 지정 ID는 `/game-map?vehicle=pcars1-p01-a`처럼 열 수 있다.

- **현재 경기 따라가기**: 게임의 코스/경기 변경에 맞춰 선택과 도면을 바꾼다.
- **경기 기록·랩 선택**: 이전 경기 또는 특정 랩의 궤적을 조회한다. 기록을 직접 선택하면 현재 경기 자동 추종을 해제한다.
- **회색 선**: 해당 코스에 등록된 참고 도면/주행선. **색상 선**: 저장한 주행 속도. **초록 점**: 현재 유효 수신 위치.
- **확대·드래그·전체 보기**: 기본은 궤적 전체 범위에 맞춘다. 직접 확대/드래그하면 해당 시점을 유지하고, 전체 보기로 자동 맞춤을 복구한다.
- **JSON/SVG 저장**: 현재 조회한 궤적·도면을 내려받는다. JSON에는 좌표·속도·랩·시각·연속 구간·도면 출처를 포함한다.

일시정지·메뉴·통신 단절·브라우저 연결 지연에는 초록 현재 위치 표시를 지운다. 저장한 과거 궤적은 조회 자료로 남긴다. 서로 다른 랩, 위치 순간 이동, 일시정지 전후, 수신 단절 구간을 선으로 연결하지 않는다.

## 코스 지도는 어떻게 준비되는가

1. **기본 참고선**: `Zolder / 기본(빈 variation)`과 `Dubai Autodrome / Club`의 공개 MIT 커뮤니티 주행선을 포함했다. 실제 게임에서 수집한 공식 서킷 경계 도면은 아니다. 원본은 2018년 자료이며 사용자의 PCARS 1에서 위치 정합을 직접 검증하지 않았다. 게임이 다른 코스 이름/버전을 보내면 추측해서 붙이지 않는다.
2. **자동 학습**: 미등록 코스는 현재 궤적부터 표시한다. 유효한 연속 완주 랩을 관찰하면 해당 코스의 참고선으로 저장하고 다음 경기·재실행에도 불러온다. 시작/끝 부근의 게임 랩 거리, 다음 랩으로의 진행, 최소 표본 수를 확인하며, 무효 랩·중단된 랩은 완성된 도면으로 저장하지 않는다. 학습된 선은 운전자가 달린 경로이며 도로 가장자리와 다르다.
3. **지도 JSON 등록**: 다른 기기/기록에서 내보낸 도면을 가져온다. 서킷 이름과 코스 버전이 선택한 기록과 같아야 한다. 등록한 도면은 기본 참고선보다 우선한다.
4. **PNG/JPEG 배경 등록**: 해당 서킷의 도면 이미지를 게임 좌표 범위에 맞춰 등록하면 궤적 아래에 겹쳐 표시한다. 이미지의 오른쪽이 +X, 위쪽이 +Z가 되도록 준비하고 이미지 전체에 해당하는 `[최소 X, 최소 Z, 최대 X, 최대 Z]`를 입력한다. 회전·투영·왜곡 보정이 필요한 일반 지도 이미지는 먼저 좌표 방향을 맞춰야 한다. 파일을 넣는 것만으로 자동 정합되지는 않는다.

따라서 **등록 도면은 주행 전부터**, **미등록 코스는 첫 주행부터 궤적이**, **유효 완주 후에는 학습한 전체 참고선이** 표시된다. 모든 게임 코스의 공식 도면을 미리 제공하는 기능은 아니다.

등록 화면은 지도 아래의 **서킷 도면 등록**을 펼쳐 사용한다. 수신기에서는 게임을 일시정지하거나 정차한 뒤 등록한다. 등록에는 설정한 `UNIMOTORS_TOKEN`이 필요하다. 이미지 상한은 1MB이며 PNG/JPEG를 받는다. 외부 이미지 URL이나 SVG 업로드는 받지 않고 로컬 이미지 데이터를 도면에 포함하므로 조회 중 외부 지도를 호출하지 않는다. PC 수신기와 피트 서버의 사용자 등록 도면 저장소는 각각 별도이며, 같은 JSON을 양쪽에 등록할 수 있다.

지도 JSON의 최소 예시는 다음과 같다. 좌표는 예시이며 실제 서킷을 나타내지 않는다.

```json
{
  "version": 1,
  "track": "Example circuit",
  "variation": "Short",
  "source": "도면 출처와 보정 근거",
  "paths": [[[0, 0], [100, 0], [100, 100], [0, 0]]]
}
```

이미지 등록은 `image: {"data_url":"data:image/png;base64,...", "bounds":[minX,minZ,maxX,maxZ]}`를 추가한다. 지도 파일의 모든 위치는 게임 X/Z 좌표이며 위·경도가 아니다.

## 기록 방식

- 선택된 참가자 레코드의 **signed int16 X/Y/Z**, 랩 거리와 트랙 길이를 해석한다. 현재는 UDP 정수 좌표를 사용하며 추가 소수 정밀도 비트를 복원하지 않는다.
- 원본 필드는 v7 CSV의 `meta.input.frame`에 `world_x/y/z`, `lap_distance`, `track_length`, `path_part`로 저장한다. 실제 GPS의 `lat/lon/fix`를 게임 좌표로 채우지 않는다.
- 수신기 DB에 `game_track_points` 조회 인덱스를 함께 기록한다. 서버도 표본과 좌표 인덱스를 같은 트랜잭션으로 커밋한 뒤 ACK를 보낸다. 재전송/동일 프레임의 반복 표본은 지도에 중복 점을 만들지 않는다.
- 재실행은 새 게임 세션으로 시작하지만, 이전 경기의 좌표와 등록·학습한 도면은 보존한다. 수신기 `state/pcars1/race_state.sqlite3`, 피트 서버 기존 DB를 사용한다.
- UI에는 최근 100개 경기/코스 묶음을 표시한다. 지도 API는 한 조회에서 앞의 최대 20만 좌표를 읽고, 긴 기록은 기본 약 1.2만 점으로 간소화한다. 간소화 여부를 화면/JSON에 표시하며 구간 ID를 유지해 단절을 잘못 연결하지 않는다. 전체 수집 자료는 원래 CSV/DB에 남는다.
- 피트의 기존 차량/구간 삭제를 사용하면 해당 게임 좌표 인덱스도 함께 지운다. 별도로 등록·학습한 코스 도면은 보존한다.

좌표는 CSV 표본 주기(기본 0.2초)로 기록하며 원본 UDP 전 패킷 저장과 다르다. 게임 위치 궤적은 게임 화면 가독성·배치·과제 분석 자료이며, 실제 차량 GPS·에너지·제동 거리의 검증값이 아니다.

## 검증

- 전체 pytest **114개 통과**. 좌표 오프셋·부호, CSV 보존, 재시작 후 조회, 서버 ACK와 원자적 저장, 재전송 중복 제거, 랩/일시정지/통신 단절/순간 이동/코스 변경 분리, 완주 지도 학습과 무효·중단 랩 제외, 이름·레이아웃별 도면 매칭, 등록 지도 지속성, 삭제와 잘못된 지도 입력 거부를 포함한다.
- 실제 수신 프로세스에 **가상 UDP** → CSV/DB → 피트 서버/ACK → 로컬·피트 지도 UI를 시험했다. 커스텀 JSON/PNG 등록, 궤적 JSON 내보내기, Zolder 참고선 자동 선택과 이전 코스 이미지 제외, 현재 위치의 일시정지/수신 중단/브라우저 단절 처리, 확대/전체 보기, 3가지 화면 폭을 확인했다.
- 증거: `.qa/pcars-map-custom-synthetic.png`, `.qa/pcars-map-zolder-synthetic.png`, `.qa/pcars-trace-export.json`. 그림 속 주행 입력은 합성값이며 실제 사용자 게임 주행이 아니다.
- 실제 PCARS 1 실행, 실제 S25/iPad/Pi/DSI, 해당 게임 패치에서의 좌표·도면 정합, 학생 실험은 아직 수행하지 않았다.

재현: `python -m pytest -q`, `python scripts/pcars-browser-smoke.py`. GitHub Actions에도 같은 검증을 포함한다. 서버를 평면 설치할 때 `game_tracks.py`, `game_track_viewer.html`, `pcars_track_maps.json`, 라이선스 고지 파일을 함께 배치하며 `install-server.sh`에 반영했다.
